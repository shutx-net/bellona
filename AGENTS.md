# AGENTS.md

Guidance for people and coding agents who work on Bellona.

## Project

Bellona is a local-first workflow engine that runs existing coding agents (Claude Code first) as external
processes and controls planning, implementation, evaluation and verification. It is written in Go with the
standard library only.

`SPEC.md` is the authority. Appendix A of `SPEC.md` (the requirements index) is generated by
`docs/tools/gen_index.py`: edit the `ROWS` in that script and run it, and never edit the tables by hand.

## Environment

Go, Git and Python come from `flake.nix`, and `GOTOOLCHAIN=local` keeps Go from downloading another toolchain.
Run every command through the dev shell:

```sh
nix develop --command <cmd>
```

While `flake.nix` and `flake.lock` are not tracked by Git (an uncommitted checkout), Nix cannot see them through
the Git fetcher; use `nix develop path:. --command <cmd>` instead.

## Commands

```sh
nix develop --command bash -c 'test -z "$(gofmt -l .)"'              # formatting, fixtures under testdata included
nix develop --command go vet ./...
nix develop --command go test -race ./...                            # add -short to skip the tests that run the Go toolchain
nix develop --command python3 docs/tools/gen_index.py SPEC.md --check-only
nix develop --command go build ./cmd/bellona                         # writes ./bellona, which Git ignores
```

CI (`.github/workflows/ci.yml`) runs the first four on every pull request and every push to `main`. It installs
Go with `actions/setup-go` from `go.mod` instead of using Nix.

## Layout and dependency direction

| Package | Role |
| --- | --- |
| `internal/strictjson` | Strict JSON for every contract (`encoding/json/v2` only); checks the contract convention |
| `internal/domain` | Identifiers, Run/Phase/Attempt states, roles, event catalogue, limits, artifact references, Run file layout |
| `internal/artifact` | Typed artifact contracts (task, implementation result) |
| `internal/version` | The engine version |
| `internal/fsm` | The three transition tables as data, check functions and the workflow digest |
| `internal/projection` | The pure reducer (`Apply`, `Replay`), the projected state and the snapshot shape |
| `internal/storage` | Run directory, lock, immutable artifacts, event journal, snapshot and crash seams |
| `internal/config` | Configuration layers, validation and the merge into the effective configuration |
| `internal/manifest` | The Run manifest: freezing, compatibility and change detection |
| `roles` | Embedded role definitions (placeholders in M0) |
| `internal/agent` | The provisional `AgentRuntime` contract |
| `internal/runtime/fake` | A scripted fake runtime for tests |
| `internal/engine` | Single-writer control loop, Run creation, resume and crash recovery; the only importer of `storage` |
| `internal/evals` | Formats of the evaluation tasks and result records; the sample tasks are in `evals/tasks` |
| `internal/testutil/gitrepo` | Temporary Git repositories for tests |
| `internal/archtest` | Architecture tests |
| `cmd/bellona` | The command line; `version` only in M0 |

Packages import only what is listed here (each also imports the standard library):

- no module imports: `strictjson`, `version`, `testutil/gitrepo`
- `domain` and `evals` import `strictjson` only
- `artifact`, `config`, `storage` import `domain` and `strictjson`
- `fsm`, `roles`, `agent` import `domain`
- `projection` imports `domain`, `fsm` and `strictjson`
- `manifest` imports `config`, `domain`, `fsm`, `strictjson` and `version`
- `runtime/fake` imports `agent` and `domain`
- `engine` imports `agent`, `artifact`, `config`, `domain`, `fsm`, `manifest`, `projection`, `storage`,
  `strictjson`, `roles` and `version`
- `cmd/bellona` imports `domain`, `fsm` and `version`

`internal/archtest/arch_test.go` holds the authoritative matrix. Whoever adds a package or a new import must
update it deliberately; the test fails for a package that is not listed.

## Rules

- Standard library only: no third-party module, and no `encoding/json` v1. Write documentation, comments and
  messages in English.
- Contracts follow the strict JSON conventions: decode and encode them with `internal/strictjson`; a member is
  optional if and only if its tag has `omitzero`; JSON `null` is never valid; a value that is unset or not
  measured is an absent member, never zero.
- Only the engine's control loop commits events or writes Run files. The reducer is pure: no clock, no
  randomness, no I/O.
- Bellona never deletes Run files on its own.
- Tests use `t.TempDir()` as the state root and never touch the user's real state or Git configuration.
- Internal packages do no terminal I/O: `cmd/` passes readers, writers and loggers in.
- The transition tables in `internal/fsm` must equal the tables in `SPEC.md`. A change needs a `SPEC.md` edit, a
  `WorkflowVersion` bump and a new digest golden value.
- The `AgentRuntime` contract in `internal/agent` is provisional until M1a.
- Scope follows the milestones of `SPEC.md` §18 and Appendix A; do not build ahead of the current milestone.

## Contract versions

A Run records the versions of the contracts it was written under in its manifest, and `Open` refuses a Run whose
versions this engine does not support. A change to a contract therefore bumps its version in the same change:

- Any change to the event types or to the members of an event payload bumps `domain.EventSchemaVersion`.
- Any change to the configuration schema (`bellona.json` and the frozen `policy.json`) bumps `config.SchemaVersion`.
- Any change to the manifest schema (`manifest.json`) bumps `manifest.SchemaVersion`.
- Any change to the transition tables bumps `fsm.WorkflowVersion` and replaces the golden digest in
  `internal/fsm/fsm_test.go` in the same change.
